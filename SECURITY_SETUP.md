# Arizona Lavka Marketplace - Безопасная настройка

## Обзор

Этот документ описывает меры безопасности, внедренные в проект Arizona Lavka Marketplace, и объясняет, как правильно настроить приложение с использованием безопасного управления секретами.

## Внедренные меры безопасности

### 1. Безопасное управление секретами

Мы внедрили систему безопасного управления секретами, которая:

- Предотвращает хардкодинг чувствительных данных в исходном коде
- Поддерживает несколько источников получения секретов (файлы, переменные окружения, зашифрованные хранилища)
- Использует шифрование для хранения секретов на диске
- Поддерживает Docker secrets для продвинутых конфигураций

### 2. Приоритет источников секретов

Система получения секретов использует следующий порядок приоритета:

1. Зашифрованные файлы в директории `secrets/` (через `SecretsManager`)
2. Docker secret файлы (если указаны переменные *_FILE)
3. Переменные окружения
4. Значения по умолчанию

### 3. Защита от утечки секретов

- Все чувствительные данные теперь извлекаются из безопасных источников
- В новой конфигурации Docker Compose (`docker-compose.secure.yml`) используются только ссылки на секреты
- Добавлена валидация обязательных секретов при запуске приложения

## Установка и настройка

### 1. Генерация секретов

Для генерации безопасных случайных значений для всех необходимых секретов выполните:

```bash
cd D:\code\python\arizonalavka
python generate_secrets.py
```

Это создаст директорию `secrets/` с файлами для всех необходимых секретов.

### 2. Настройка собственных значений

По умолчанию скрипт генерирует безопасные случайные значения, но для продакшена вам нужно будет:

1. Заменить Cloudflare Turnstile ключи на настоящие (полученные с https://www.cloudflare.com/products/turnstile/)
2. Заменить учетные данные Gmail на настоящие
3. Убедиться, что JWT секрет имеет достаточную длину (минимум 32 символа)

### 3. Запуск приложения с безопасной конфигурацией

Для запуска приложения с использованием безопасной конфигурации:

```bash
docker compose -f docker-compose.secure.yml up -d
```

### 4. Альтернативные способы предоставления секретов

Помимо файлов в директории `secrets/`, вы можете предоставлять секреты следующими способами:

#### Через переменные окружения:
```bash
export POSTGRES_PASSWORD=your_secure_password
export JWT_SECRET_KEY=your_jwt_secret
export GMAIL_APP_PASSWORD=your_gmail_app_password
```

#### Через Docker secrets (в Docker Swarm):
```bash
docker secret create db_password /path/to/password/file
docker secret create jwt_secret /path/to/jwt/secret/file
```

## Архитектура системы безопасности

### Модуль `utils/secrets_manager.py`

Основной модуль, обеспечивающий безопасное получение и хранение секретов:

- Использует `cryptography.fernet` для шифрования секретов на диске
- Поддерживает защищенное хранение в зашифрованных файлах
- Предоставляет глобальный экземпляр для удобного доступа
- Включает валидацию обязательных секретов

### Обновленный `config.py`

Конфигурационный файл был обновлен для использования новой системы управления секретами:

- Все чувствительные поля теперь получают значения через безопасный механизм
- Сохранена совместимость с существующими способами предоставления конфигурации
- Добавлена дополнительная валидация для критических параметров безопасности

## Рекомендации по безопасности

### Для продакшена:

1. **Используйте надежное решение для управления секретами** (HashiCorp Vault, AWS Secrets Manager, Azure Key Vault и т.д.)
2. **Не храните файлы секретов в системе контроля версий**
3. **Регулярно меняйте секреты**, особенно JWT ключи и пароли
4. **Используйте разные секреты для разных сред** (разработка, тестирование, продакшен)
5. **Ограничьте доступ к файлам секретов** с помощью прав доступа к файловой системе

### Мониторинг безопасности:

1. **Логируйте попытки доступа к секретам** (но не сами секреты!)
2. **Настройте алерты** на необычную активность, связанную с аутентификацией
3. **Регулярно проверяйте** наличие уязвимостей в зависимостях

## Проверка настроек безопасности

После настройки вы можете проверить, все ли обязательные секреты доступны:

```python
from backend.utils.secrets_manager import validate_required_secrets

required_secrets = [
    'POSTGRES_PASSWORD',
    'JWT_SECRET_KEY',
    'CLOUDFLARE_TURNSTILE_SECRET_KEY',
    'GMAIL_APP_PASSWORD'
]

validation_results = validate_required_secrets(required_secrets)
print("Validation results:", validation_results)
```
