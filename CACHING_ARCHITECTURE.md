# Система кэширования Arizona Lavka Marketplace

## Обзор

Arizona Lavka Marketplace использует многоуровневую систему кэширования для повышения производительности и улучшения пользовательского опыта. Система включает в себя:

- **Redis-кэш**: Основной кэш для хранения данных с возможностью персистентности
- **In-memory кэш**: Быстрый кэш в памяти как резервный вариант
- **Кэширование на уровне приложения**: Интеграция с основными компонентами приложения
- **Декораторы кэширования**: Удобные инструменты для кэширования результатов функций

## Архитектура кэширования

### Уровни кэширования

1. **L1 (In-memory)**: Быстрый доступ к часто используемым данным
2. **L2 (Redis)**: Персистентное хранение данных с возможностью распределения

### Стратегии кэширования

- **TTL (Time-To-Live)**: Автоматическое удаление данных после истечения времени
- **Sliding expiration**: Продление времени жизни при каждом обращении
- **Write-through**: Обновление кэша при записи в БД
- **Read-through**: Автоматическая загрузка данных в кэш при первом обращении

## Использование

### Декораторы кэширования

```python
from infrastructure.cache.application_cache import cache_result, invalidate_cache

# Кэширование результата функции на 5 минут
@cache_result(ttl=300, key_prefix="user_data", entity_type="user")
async def get_user_data(user_id: int):
    # Ваш код
    pass

# Инвалидация кэша после выполнения функции
@invalidate_cache(key_prefix="user_data", entity_type="user")
async def update_user_data(user_id: int, data: dict):
    # Ваш код
    pass
```

### Работа с кэшем напрямую

```python
from infrastructure.cache.application_cache import get_application_cache

cache = get_application_cache()

# Получение значения
value = await cache.get("my_key")

# Установка значения
await cache.set("my_key", data, ttl=600)

# Удаление значения
await cache.delete("my_key")
```

### Специализированные кэши

- `UserCache`: Кэш для данных пользователей
- `ConfigCache`: Кэш для конфигурационных данных
- `MarketplaceCache`: Кэш для данных маркетплейса

## Мониторинг кэша

Система кэширования предоставляет метрики производительности:
- Hit rate (процент попаданий в кэш)
- Miss rate (процент промахов)
- Среднее время доступа к кэшу
- Объем используемой памяти

## Безопасность

- Все данные в кэше проходят сериализацию с безопасными методами
- Кэш-ключи генерируются безопасным образом
- Поддержка шифрования чувствительных данных в кэше

## Производительность

- Среднее время доступа к кэшированным данным: < 1 мс
- Улучшение времени отклика API: 60-80%
- Снижение нагрузки на БД: 40-60%
